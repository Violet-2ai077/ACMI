# BS1：只验证工作段边界

日期：2026-11-16，Asia/Shanghai。实际研究已完成，停止调用。

## 结论

**在本轮四个八轮合成对话中，模型在正常回答的同一次生成里，正确完成全部
28 个后续工作段边界判断；但首轮有一次完整回答漏掉标记，协议有效性为 31/32。
因此，当前证据支持这个受控范围内的边界划分能力，不支持宣称全程标记可靠。**

冻结的严格局部门槛要求四条轨迹连初始化标记都全程正确，实际仅 3/4 条满足，
`strict_local_criterion_met=false` 保留。没有把它改成 PASS，也没有把漏标改成
UNRESOLVED。28 个分母在运行前就排除了四个初始化轮，不是看结果后排除失败。

## 1. 与前一轮不同：只问是否切段

本轮依据 Owner 后续明确授权“可以，就按照这个去验证一下”，单独建立 BS1。
不是恢复 FM1，也不修改 FM1 的原始结果或冻结材料。历史 G1/P-G 结论不变。

- 单一 inline 臂，标记只有 CONTINUE、NEW、UNRESOLVED。
- 不提供任务 UUID、空闲 UUID 槽位、任务目录或目标/工作状态对象。
- 不要求恢复长期任务身份；离开某项工作后再返回，一律 NEW。

- 全部 CLOSED-LOOP；FROZEN-REPLAY、D、C0、第二次补标和 LLM Judge 均为零。
- 所有场景为新合成材料，中文请求为主，包含一次翻译成英文的工作步骤。
  有些返回关系明确说出，有些只通过工作对象体现；不是无任何线索的任务发现。

模型收到的是固定边界规则 + 普通对话。第二条系统消息只含协议和 source IDs，
不含私有故事名、类别、oracle、段号或答案断言。路由会话 ID 仅用于 HTTP 路由，
不是任务身份。请求重建核验确认这些隔离条件。

## 4. 真实问题与证据定位

### 初始化完整回答漏标，不能掩盖

`evidence/01-login-notice-t1-a1/result.json` 的 `/content` 是：

> 最小修复：在统一请求层优先拦截 401，清除过期会话并跳转登录（或弹登录框），同时确保加载状态在 `finally` 中关闭；不要让 401 落入普通错误分支后继续转圈。

没有任何 boundary 标记。原始 SSE 已完整结束，terminal/内容重解码核验均通过；
不是采集截断、超时或响应大小问题。观察到的是**返回协议失败**，不是 NEW/CONTINUE
语义误判。没有补标、默认算成功或补请求。内部为什么漏标，当前黑盒证据无法确定。

该原始未标记正文仍逐字进入 t2 历史，没有用正确标记替换；t2 至 t8 仍全部正确。
程序将首段初始化为 1 不等于替模型补全标记：`observed_segment` 在失败首轮记 null，
该轨迹严格全程成绩为 false。轨迹字段 `all_boundaries_correct` 实际按冻结实现
包含初始化和协议要求，不要只凭字段名字把它误读为七个边界中有一个错。

### 一次回答词法失分，不是边界失分

`evidence/30-sibling-projects-t8-a1/result.json` 的回答明确请求选择测试清单或
签到表，并正确输出 UNRESOLVED。但冻结的回答断言要求“哪 / 确认 / 选择”之一，
模型用了“请明确……是指……还是……”，所以 `answer_minimal=false`。

原分保留：基本词法检查 **30/31** 可评回答通过，另 1 个首轮协议无效输出的
该项为 null；即 32 次输出中 30 通过、1 词法失败、1 未评。不能改成 31/31，
也不能把它说成没有完成澄清。无 C0 或语义 Judge，不能证明回答质量不劣化。

### 不是只依赖显式“切换”词

案例摘录及原始文件摘要见 `analysis/supplement.json`：

- #9：用户说“另外”，实际是给登录修复补回归测试，输出 CONTINUE。
- #10：两个项目都谈导入重复，但北桥改为南桥的独立设计，输出 NEW。
- #11：转述“现在开始一个新任务”，实际仍要求义卖分工，输出 CONTINUE。
- #14：从南桥回到北桥，虽没有“回到”口令，输出 NEW，不恢复段 1。
- #21：离开会议通知回到登录修复，输出 NEW。
- #27：把同一义卖方案翻译英文，输出 CONTINUE。
- #29/#30：明确没有选定两个目标之一，输出 UNRESOLVED 并提问。

这支持已覆盖的对比，不证明模型在隐晦、冲突或多目标混杂的请求中也可靠。

## 6. 能说什么、不能说什么及停止

**可以说：**在短、单一当前目标、按公开政策定义的合成对话中，边界判断可以
从身份和状态维护中分离，并已取得实际全部后续判断正确的证据。这不是只有
“每轮换一个数字”的演示：应保持的步骤和应切换的工作都被实际覆盖。

**不能说：**任意自然对话都能正确切分；完全自发而无需指令；没有漏标风险；
已经支持并行任务/同轮多目标、隐含歧义、长对话、跨 Session、旧身份恢复或
可靠工作状态。两个 UNRESOLVED 案例都显式声明未指定对象，不代表复杂指代能力。
没有独立随机样本、重复采样或对照，不给出统计总体准确率或架构因果结论。

本轮冻结严格局部门槛仍为 false，原因是初始化漏标；这是协议可靠性问题，
不能反过来把 28 个正确边界观察解释为边界能力不成立。下一步如另有授权，应
仍限定于更自然、更弱切换线索的边界稳健性和漏标问题，不自动升级到 UUID/状态
维护。本轮已停止，没有新批次、工程资格链或进一步研究阶段在运行。

结果与证据提交在当前研究分支；main 保持 `d854c36c5083ff5f7c08ec851e1af3cf8b6567c9`。
