# ACMI 0.9.19：D 终止策略与 B 空白语法独立修订提案

日期：2026-11-15。状态：**DRAFT / 待 Owner 审核，未实施、未启用。**

本文件仅提交两个可分别批准的协议修订。不是新运行授权，不是新冻结包，
不改变旧分数，不重解析旧模型输出，不重放实验，不恢复任何已停止的账本。
本轮只进行了源码、既有报告和摘要的只读核对，以及文档自查；没有独立评审代理。

## 1. 建议决议

| 项目 | 推荐方案 | 本次不推荐 |
| --- | --- | --- |
| R-D：诊断超时与停止 | 保持每次生成 180000 ms；仅对满足严格证据条件的 D2 截止超时作局部终止，随后走固定计划下一坐标 | 延长到 360 秒、进度重置计时、重试、把 D 移到最后、跳过 D |

不因本提案自动新增对照批次、重复次数或额外调用。

## 2. 不变项及“计划不变”的确切含义

研究问题仍是：LLM 能否在正常回答用户的**同一次生成**中，自主识别、标记并持续维护自己的工作任务。

- A/B 仍是同次生成；D 仍是单独的两次生成诊断，不进入 A/B 自主标记成绩或最终 GO。
- C1/C2/C3、六个场景、难度标签、完整对话、oracle、规范 UUID、出生映射、关系、状态真值、负例和答案谓词不变。
- public corpus、oracle、plan 和四份 prompt 的 **7 个冻结文件摘要不变**。
- 固定 seed、162 个 block、全部坐标及其先后顺序不变：576 个生成槽位，432 CLOSED-LOOP、72 A/B replay、72 D 生成。
- D 仍有 36 对 D1/D2；每条件 192 个生成槽位。不得补样、重排、跳过或重新随机化。
- 模型别名、reasoning 设置、16384 输出 Token 请求上限、131072 输入字节上限、1048576 响应字节上限及路由不变。
- A/B/C0 与 D1 的失败即全局停止规则不变。R-D 有意修改的是一个狭窄的 **D2 运行终止规则**，不是坐标计划。
- 无第二个 LLM Judge、无 JSON 自动修复、无生成重试；任务提案仍不写入正式 Host/Graph。
- 不修改 Gate 1 的 25 个保护文件或既有接口；不降低现有 GO 门槛、错误率门槛或统计要求。

不得称新旧运行条件“完全相同”：R-D 改变诊断失败后的继续资格，R-B 改变语法接受语言。
即便研究问题、计划和真值不变，这两项也必须作为显式实验版本差异披露。

## 3. 已有证据能说明什么

基线是 development-r3，manifest SHA-256：

`a335bd5c340249021e534a3a8de23f079e504308cae41bd8350ea6c07470d168`

- 第 29 次请求为 `delta-ambiguity / C3 / D / FROZEN-REPLAY / t8 / marker`。
  180.413 秒超时，写入占比 4.26%；收到 237401 wire 字节、16017 reasoning 字节，
  reasoning 在约 180.2 秒仍到达，但没有 content 或最终 usage。
  不能据此证明“只需更长时间就能成功”，也不能证明模型能力不足或服务故障。
- 六份 B 输出在旧解析器均报 `frame`；已有只读扫描记录了每份两处帧间空白。
  旧语法不消费这种空白。它证明了实际协议符合性问题，**不证明删除空白后语义必然正确**。
- 所有旧分数、失败类型和未完成状态保持权威地位。提案不是对它们的撤销或改分理由。

源码核对还发现，当前传输结果不能直接支持安全的局部继续：

1. `evidence_complete` 同时受写入成功与 body 是否读完影响，不能区分“已归档的完整截断前缀”和“归档缺失”。
2. 超时可覆盖之前记录的解码/响应错误，不能只凭最终 `error_code=timeout` 判断豁免资格。
3. `reader.cancel()` 当前没有等待确认；也尚未单独证明截止时已交付片段与归档边界完全对应。

因此，**禁止仅把当前 error 改成 success，或让 runner 遇到 D 的 timeout 就 continue**。
下述可审计终止证据是 R-D 生效的前置条件；既有 r3 不能追认成新规则下的可继续运行。

## 4. R-D：保持时限，狭窄隔离 D2 截止超时

### 4.1 时限与资源

- D1、D2 各自仍为 180000 ms；起点保持现有定义：发送前校验完成、即将执行唯一一次原生 Fetch 时。
- 接收到 reasoning/content、心跳或 usage 都不重置计时。无阶段续时，无补发、换模型或降低 reasoning 后重试。
- 允许实际终止时间有可观测的调度/归档开销，但不把超时后的输出重新认定为时限内完成。
- 新增最多 **5000 ms 的本地 abort/清理确认窗口**。它不是额外模型生成预算，不等待答案完成，
  不开放第二次请求；无法确认本地读取链关闭就全局停止。
- 5000 ms 是待审定的工程初值，不是从 r3 推出的概率或已验证上界；只允许未来离线故障注入验证，不能边跑真实请求边调大。
- 本地 abort 不证明服务端已停止计算或不再计费；费用未知时保留 null，不写零。

不推荐当前就把 D2 改为 360 秒：一次截尾样本不足以支持该数值，且会同时改变耗时、资源竞争和完成率。
以后如研究时限敏感性，应另行预注册，而不是将本次失败当作自适应加时触发器。

### 4.2 唯一可局部终止的情况

只有以下条件**全部成立**，D2 才可登记为 `DIAGNOSTIC_CENSORED_DEADLINE`：

1. 当前精确坐标是 dev / D / FROZEN-REPLAY / marker，属于冻结计划下一槽位。
2. 自身 D1 已成功持久化，D2 请求绑定的原始答案摘要与该 D1 一致。
3. 唯一一次请求已发出，HTTP 200，响应类型为预期 SSE；不存在之前发生的 HTTP、SSE、UTF-8、身份或其他协议错误。
4. 停止原因仅为本地 180000 ms 截止；未触及字节上限、未发生证据写入失败、操作员取消或进程失联。
5. 所有实际交付到 Harness 的原始片段均已按顺序归档；读完远端 body 不作要求。
   必须区分截止前、清理期交付的片段，并保留后者，但任何迟到内容不得使本次变为成功。
6. 已确认本地读取/回调链关闭，不会继续向已结算尝试写入；不能证明则全局停止。
7. terminal 事实与完整账本审计成功，持久化截尾结算成功，冻结/请求/D1 绑定仍一致。
8. 当前是已授权的 uncapped 费用策略；不得把该豁免用于绕开未来有限预算下的未知费用风险。

这些事实必须由传输层、账本审计和冻结策略共同证明，不能由调用者传入一个 `allow_continue=true`。
特别是“最终超时码”不能遮蔽更早的错误。仍有不确定性就全局停止。

### 4.3 结果与运行控制分离

提案中的记录语义如下，仅为字段设计，不是当前实现或可执行配置：

| 维度 | D2 合格截止截尾的值 |
| --- | --- |
| 尝试结果 | `timeout`，不是 success |
| 模型结果完整 | false |
| 已接收前缀完整性 | 经审计 verified；不等于完整远端响应 |
| 本地读取链 | confirmed closed |
| 结算类型 | `diagnostic_censored` |
| 后续运行资格 | `continue_next_scheduled_coordinate` |
| 调用计数 | 消耗 1 个原有生成槽位，永不返还 |
| 实际费用 | 无证据则 null；不释放成“免费调用” |

继续的是**下一条原定坐标**，不是继续当前模型生成，也不是重做 D2。
若断电发生在请求发出后、合格截尾结算落盘前，仍视为未完成预留，禁止恢复时自动发送。
仅未来 v4 的合格结算已完整落盘且复核通过时，恢复流程才可进入下一原定坐标；
不得凭内存里的 continue 决定恢复，也不得重发该 D2。

新行为需要新账本语义版本（建议 `gate2-run-v4`）与冻结的 `D-180-LOCAL-v1` 策略。
不重解释 v1/v2/v3 的 error，不迁移或清除旧 halted 状态。未来新批次从原计划首坐标开始，
不从 r3 的第 30 条续跑；已见开发数据的再使用必须披露。

### 4.4 其他情况保持原行为

| 情况 | 后续动作 |
| --- | --- |
| D2 合格截止截尾 | 本次失败/截尾入账，审计后按原顺序进入下一坐标 |
| D1 超时或失败 | 全局停止；不得捏造 D1，也不跳过该 D2 |
| A/B/C0 传输失败 | 全局停止 |
| 任意组 HTTP 非 200、服务限流/拒绝、协议错误、字节超限、证据失败 | 全局停止 |
| 任意组操作员取消、进程崩溃、遗留锁、冻结/请求摘要失配 | 全局停止 |
| D2 `length` 截断、非截止原因的断流、清理未确认 | 全局停止；不扩大本次豁免 |
| 完整传输但任务标记无效 | 保留原始输出并按冻结 Evaluator 记失败；沿用既有行为，不重新生成 |

有意不引入“累计若干 D2 失败后改变样本量”等自适应规则。至多 36 个既定 D2 槽位，每个仅一次。
代价是实际执行可能比旧版早停前缀更长：36 个 D2 的生成时间窗口合计最多 6480 秒，
清理窗口合计最多 180 秒；这些只是该阶段的窗口合计，不是整批墙钟或费用上界。
若日后需要健康检查或熔断阈值，应另行批准；不能在本批看到结果后临时决定。

## 5. R-B：显式、有限的帧边界空白语法

### 5.1 版本与边界

建议 profile 名称：`B-inline-v1-ws1`。现有 `<|acmi:...:v1|>` 标记、JSON 字段、
ENVELOPE、任务语义和 oracle 不变；接收语言版本由冻结 manifest/runtime 明确选择。
**不是检测旧解析失败后自动启用的 fallback。** 未知 profile 必须拒绝。

首轮推荐保持 B prompt 与其他三份 prompt 的原摘要不变，只研究预先声明的接收语法变化。
profile 属于 Harness 协议配置，不新增模型可见的答案示例、真值、候选判断或提示词补丁。
以后若要在 B prompt 中显式解释空白，需要单独登记生成指令变量，不能混称“只是解析器修复”。

### 5.2 允许的空白

只接受四个 ASCII 字符：SP U+0020、HT U+0009、LF U+000A、CR U+000D。
每个帧边界空白段最多 **1024 字节**；原始总字节限制不变。
这个阈值是防止无界缓冲的工程约束，不是统计结论或根据成功率调出的数值。

允许位置为：

1. 首帧之前；
2. 一个完整帧的 END 与下一完整帧的头之间；
3. 最终 commit 的 END 之后、EOF 之前。

第 1、3 项是明确提出的文件边界规则，并非隐藏扩张；Owner 如只批准帧间规则，应另命名更窄 profile。
推荐统一边界定义，避免把同一种排版空白在首尾与帧间作偶然不一致处理。

形式描述：设 `F1...Fn` 为旧 v1 中有效的完整帧序列，最终帧为唯一 commit，
`W = [SP / HT / LF / CR]{0..1024}`，则新语法接受 `W F1 W F2 ... W Fn W EOF`。
帧内部所有词法和语义约束完全继承旧 v1；既有无空白合法输出必须仍合法且语义完全一致。

### 5.3 必须保持拒绝或原样保留的内容

- 禁止 BOM、NBSP、零宽字符、Unicode 换行、VT/FF 等替代空白。
- 禁止改写标记大小写、在标记名字内部插空格、补标记、补 JSON、接受围栏/注释/解释性前后文。
- 仍拒绝重复 JSON key、非有限数、非法转义、原始未转义标记 JSON、未知字段、缺字段和无效 UUID/引用。
- 仍拒绝错误的帧顺序/前向引用、第二个 commit，以及 commit 后任何非允许空白的内容。
- 只有空白而没有完整帧，或 JSON/帧被截断，均不得判为成功。
- JSON 字符串、证据 quote、用户答案正文中的空白**逐字保留**；不对这些内容做 trim、折叠或替换。
- 答案正文中的换行是用户可见内容，不是可忽略的帧边界空白；转义标记仍按原规则处理。

### 5.4 解析方式与流式兼容

未来实现应在“期待帧头”及“commit 后等待 EOF”的状态识别空白，而非先全局 trim/正则替换再交给旧解析器。
原始字节始终归档；可单独记录被语法消费的空白区间 offset/length，不能用规范化版本替换原始输出。

- 任意 chunk 边界，包括 CR/LF 分开、标记分开、UTF-8 分开，最终判断必须一致。
- 只在允许的帧边界累计空白计数；超过 1024 字节立即失败，不等待无限空白结束。
- 不把帧边界空白发送给用户，也不把正文空白吞掉。
- 未取得唯一完整 commit 与有效结束前，不把预览当成完成状态或正式 Task Graph 更新。
- 若完整 commit 后有新帧或普通字符，必须失败，即使前面的答案已经流式展示。

当前 streaming 与最终评分各有自己的解析入口。新版本必须共享同一明示 profile，
对同一字节流产生一致的规范结构；不能出现“流式接受、最终拒绝”或相反的隐式宽容。
Gate 1 冻结文件不改：未来用 Gate 2 新模块或只读适配桥复用其字段、证据及关系规则。
语法解码成 ENVELOPE 是解析步骤，不得被实现成对模型输出的重写或替代生成。
若内部借用已有 schema 校验入口，正式样本的 arm、原始字节、profile 和 provenance 始终仍是 B。

## 6. 评分、统计与跨版本比较

### D

- 计划对数保持 36；分条件/难度列出 D1/D2 dispatched、completed、deadline-censored、其他失败和未尝试数。
- D2 完成率以所有实际 dispatched D2 为分母，截尾不能从分母删除。
- 同时报 marker 可用率：按时完成且标记有效的 D2 / dispatched D2。
- 归属和 State Maintenance 的语义评分只对符合原资格的完整输出计算，并明确条件分母。
  截尾不是“语义正确”，也不强行赋一个任务状态零分；可用率中它仍是失败。
- 延迟标为 deadline-censored，不能拿 180 秒充当成功完成延迟；未尝试坐标另列，不能当成超时。
- 成本、Token、清理时间与每阶段耗时分开；无 usage 的调用不补估成零。
- D 不进入 A/B 分数或 GO；D 的新终止策略也不证明两次生成优于同次生成。

### B

- 新语法的 marker/schema validity 是新 profile 的成绩，必须明确标注，不能无说明与旧 strict-v1 混合。
- 对未来新输出，建议同时记录旧 strict-v1 的**符合性标志**作为辅助测量；仅报告标志，不“择优取分”。
  它不增加 LLM 调用，也不是对历史数据改分。Owner 未批准前，本轮不运行这一测量。
- 若新语法通过，仍须通过原 ENVELOPE、UUID/关系/证据约束，再用相同 oracle 评分。
- 空白消费不能降低实际 Token 统计、改变用户正文或伪造更低延迟；传输原始字节和真实 usage 不变。
- 语法有效性改善只能归因于新接受语言，不能自动宣称任务识别能力、状态维护能力或模型权重改善。

### 共同要求

C1/C2/C3、简单/中等/困难、A/B/C0/D、FROZEN-REPLAY/CLOSED-LOOP 继续分开。
旧批次早停、新批次可能继续，观测覆盖将不同；禁止把仅完成样本的均值作无条件前后因果比较。
不得把已观察开发样本恢复为“未见验证集”，不得据此重算或放宽确认性 GO 门槛。

## 7. 历史证据与新版本隔离

1. r1/r2/r3 的原始输入、输出、reasoning、wire、评分报告、摘要、journal head 和 halted 状态不变。
2. 不为六份旧 B 输出产生去空白后的新正式成绩，不为旧 D2 增补 marker 或撤销失败。
3. 本提案只基于已有只读报告和源码作分析；没有重新运行旧 parser/evaluator，也没有离线或在线实验。
4. 将来获批后，新增 profile/policy、账本语义和报告器必须另行冻结；不得覆写 development-r3。
5. 新 manifest 除绑定源码和运行参数外，应绑定两项策略 ID、Owner 批准记录、独立测试材料和摘要。
6. 新 pin 的“先于输出”仅指新 revision 的输出；必须披露这些变更源于已见的开发集失败。
7. 如果两项同时启用，一批最多仍为原 576 个槽位；不自动安排两批或四格额外实验来追求好结果。

## 8. 未来实现前的离线验收要求（本轮不执行）

### R-D 必须通过
