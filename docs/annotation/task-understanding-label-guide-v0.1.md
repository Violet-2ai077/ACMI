# Task Understanding 标注指南 v0.1

逐案阅读可见的对话角色、Session、当前显式 Binding 和候选。给最后
相关用户请求标注五类之一：继续当前任务、明确切换到候选中的已有
任务、新建独立目标、无任务、证据不足。寒暄或纯确认才是无任务，
有工作意图但归属不确定时标 `uncertain`。已有目标只是同主题不够；
目标缺失、已关闭、未授权或指代冲突时不要编造 UUID。

`continue_current` 的目标应为当前可用 Task，`switch_existing` 要选择
其他开放候选。其余用 null。把新任务归为既有或选择错误既有 UUID
分别记录为错误合并/错误选择；既有工作误判新建是错误拆分。

证据使用实际 turn ID；Assistant 建议不是用户接受，条件式认可也不是
最终决定。工具结果表示观察到输出，Subagent 完成表示执行结束，不
代表消费、验收、满足 Join 或任务完成。依赖需要明确方向；未知时保留
未决。可以标建议的结构，但不能标自动变更为事实。
