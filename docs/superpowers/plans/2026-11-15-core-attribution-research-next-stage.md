## 2. 工程阻塞到底阻止什么

| 层次 | 现状 | 对研究的实际影响 | 不能推出的结论 |
| --- | --- | --- | --- |
| 存储候选验收 | 八个独立耐久确认点下最低 496，要求最多 434；P-G FAIL | 当前 R-E/R-A 候选不能晋级；停止为此计数目标优化 | LLM 无法同次生成归属标记 |
| 采集完整性/容量 | R-C NOT CLOSED | 新采集路径尚无闭合的证据容量和资源保证 | 旧已完整归档输出全部失效，或退回 v4 就安全 |
| live 输出截断 | r4 最后请求触发 1 MiB 上限并全局停止 | 限制可观察的完整输出及覆盖；存在与长响应相关的非随机缺失 | 被截断请求是语义错误，或未发送坐标是模型失败 |
| 科学验证 | 有局部有效同次生成证据，持续状态维护/覆盖不足 | 可做描述性研究综合，不能确认完整机制或最终 GO | UUID 正确即状态维护成功，或协议有效即回答质量合格 |

30% append/flush-request 改善是存储候选验收要求，不是模型归属 F1。
这一区别用于解释结论，不构成把该门槛改为 N/A 或允许失败候选进入 live 的授权。
R2 仍有自身的完整证据、流式、回答质量、Token 和延迟门槛，不能以“研究版”绕过。

容量问题也不是简单的总调用数问题：既有反例中，1 MiB 已接纳前缀加下一次
3,145,729 B delivery 达 4,194,305 B；逐字节分片的 1 MiB 响应可产生
180,292,538 B 元数据。缩小批次不能证明单次 read、队列、元数据、堆内存及完整
审计成本已受控。4 MiB 仍仅为离线候选，不是 live 上限。

## 3. 已有证据支持的核心答案

**暂定研究结论：局部同次生成归属可行性已有证据；持续、准确维护任务工作状态
尚未被证实。保持 EXPLORATORY_NOT_GO，完整研究主张为 INCONCLUSIVE。**

下列为原报告摘录，不是本轮重新评分，也不跨条件合成总分：

| 已有观察 | 支持范围 | 关键限制 |
| --- | --- | --- |
| r4 35 次发送，34 次传输完成、1 次上限停止；541 次未发送 | 存在可检查的真实输入、同次输出和停止证据 | 34 次包括 C0 和 D，不能都当作 A/B 自主标记样本 |
| r4 C1/A/CLOSED-LOOP 简单 2、中等 2、困难 4 轮：schema 均有效，归属 F1 均为 1 | 有目录/身份信息时，一个 8 轮闭环中的归属信号 | 同一叙事不是 8 个独立场景；不能外推 C2/C3 |
| 上述三个难度的完整状态 exact 分别 0/2、0/2、0/4 | 身份正确没有带来完整状态维护成功 | exact 对引用、拆分和字段一致性敏感，不能直接等同所有语义都错 |
| r4 B 的 6 个已完成 replay 中，现行 profile 有效 4 个 | 新帧语法下有可解析输出 | 原严格语法成绩仍保留；没有 B 闭环，不能推导持续维护 |
| r4 C3/B/FROZEN-REPLAY 困难 1 轮完整状态 exact 1/1 | 一个提供参考历史的原始对话条件成功样本 | 不能证明 C3 自主身份建立及后续连续维护 |
| r4 D 的 5 对均传输完成；D2 schema 4/5，完整状态 exact 全部失败 | 独立生成也观察到状态困难，值得诊断 | 非自主标记成绩；预算/输入不等价时不能归因为能力竞争 |
| r4 C3/C0 的 8 轮通过有限词法检查 | 有回答对照的局部检查记录 | 不是全面回答质量证明，也不是 C1/A 的匹配对照 |

r2、r3 的 C1/A 也出现归属正确而完整状态 exact 失败；不同批次复用叙事、协议和
运行条件变化，不能作为独立重复或单因素因果实验。r3 的 B 严格语法失败不按 r4
宽空白语法重解析改分。r4 同时改变 D 超时与 B 语法，不能隔离其中一个变化的效应。

r4 上限失败坐标是 icon-invoice-switch / C1 / B / FROZEN-REPLAY / t2 / single；
已捕获 1,048,650 B，含越界 74 B，5,667 次 read，reasoning 68,997 B、content 0。
保存完整已接收前缀不等于得到完整模型回答，该请求不能提供有效任务归属结论。
34 个完成请求有 usage 合计 245,689 tokens；失败请求 usage 未知，不能称为全批次
总成本。服务 alias 已知但不可变权重身份未验证，价格/实际账单也未形成成本证据。

## 4. 阶段 S1：已有证据的只读研究综合（申请审批）

### S1.1 建立主张与覆盖账本

- 对齐 r1-r4 的冻结摘要、实际输入、输出、协议、停止事件和原报告；每个结论带
  来源路径、SHA-256 和 JSON pointer/事件位置，不复制成新的“原始证据”。
- 按 batch × A/B/C0/D × C1/C2/C3 × FROZEN-REPLAY/CLOSED-LOOP × 难度 ×
  场景族列覆盖，另列 SM1-SM6、identity_present/absent/conflicting、Session 恢复。
- 分别列 planned、sent、transport-complete、protocol-valid、scoreable 分母及缺失原因；
  保留原指标分母，附加漏斗不替换原分数。三个上下文条件不混分。
- 区分“失败”“不适用”“未观察”“资料不足”。未发送不记零，截断不判模型语义失败。
- 明确 C2/C3 闭环、B 闭环、跨 Session 身份恢复及困难状态主题哪些尚无证据。

### S1.2 聚焦 identity 正确而 state 失败

仅投影原 report.json 中已存储的 state.by_field、per_task、transition、retention、
completion、false_actual_completions、goal_revision_exact、conflict_exact、
dormant_recovery 和 state_given_correct_identity；不运行评分管线或新 JSON 修复。

- 分别列目标、验收条件、工作项状态、完成依据、决策、冲突、生命周期七类字段，
  并对应 SM1-SM6；完整 turn snapshot_exact 与 task 平均 exact 分列。
- 按实际闭环历史定位首次错误与后续传播；不能用参考历史覆盖模型旧状态。
  首轮即失败不能仅由多轮累积解释，但也不自动证明模型语义能力不足。
- 区分 planned/running/completed 及 reported/observed 完成依据。状态集合或引用
  不匹配造成的 FP 不自动命名为“虚构实际完成”。严格 exact 失败仍然保留。
- 只引用可定位的原始差异作示例，不逐条人工改判，不让另一个 LLM 做主要 Judge。
  没有已存储诊断的维度记为不可得；如需新增分析程序或评分器修复，另报明确范围。
- 真值争议/评分器缺陷进入既有版本化争议流程；引用敏感性本身不是缺陷证据。
  本阶段不修改 oracle、评分器或重算任何历史成绩。

### S1.3 对照与原因定位

按 E/G（实验/真值）-> S/P（结构/协议）-> 实际输入 C（上下文）-> M/A（能力/归属）
检查最早有证据的原因；多因素可并列，不强制选“模型能力不足”。

- A/B 和 C0 仅比较原计划中相同场景、条件、轮次、版本且具可比输入的配对。
  不以 C3/C0 替代 C1/A 对照，不挑看起来相似的问题配对。
- D 只列既定诊断对；计入 D1+D2 总 Token/延迟。缺等总预算对照时，最多形成
  能力竞争、协议负担或预算限制的候选解释，不作因果结论、不进入 GO。
- 首个用户可见 Token、端到端延迟及开销只有原记录可支持时才统计；缺失不能以
  首 reasoning Token 或传输完成时间冒充。只描述既有样本，不运行计时系列。
- 叙事是相关性分析单元，多轮及重复批次不冒充独立样本；不从小样本点估计推出
  1% 风险上界，不用 bootstrap 包装确认性结论。

交付：H1-H7 证据表、覆盖/缺失矩阵、身份与状态分离表、失败时间线、配对可用性
清单，以及有明确适用范围的中期科学结论。验收是来源可追踪、原成绩不变、分母
清楚、缺口明确，而不是要求综合报告给出正面结果。

## 5. 阶段 S2：新增证据的采集准入审议（另批）

S1 完成后，由 Owner 决定是否值得继续投入采集工程；不自动返回 P-G 优化。
先依据原文逐项列明门槛适用范围，不能自行将候选验收要求从未来路径排除。

仅审议已有基线/参考采集路径是否具备独立资格，不直接采用或修改它。r4 的 v4
已经触发响应上限；旧路径不天然具有容量、安全停机、资源或性能豁免。
必须有完整证据容量、read/队列和分片负担、恢复/审计、资源可行性，以及适用的
流式、质量、成本/延迟要求的可核查依据；“慢一点也能研究”不是准入证明。

若 Owner 确认所有新采集路径仍必须同时保留这八个屏障并通过相同 30% 计数门槛，
在当前文件账本和固定负载合同内无可晋级路径。此时提交条件阻塞与中期
INCONCLUSIVE，停止新增采集，而不是隐性减负、改分母、移出审计或再一轮计数优化。

即使某条路径未来获准，存储改进也不会消除模型响应超过 live 1 MiB 的风险。
不能事后截短证据、增加未批准停止条件、减少冻结状态负载、离线补标或用第二次
调用补全 A/B；也不能以缓冲完成后播放替代真实流式。
