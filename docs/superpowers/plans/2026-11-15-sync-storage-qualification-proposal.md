## 3. SC-S：优先显式同步，而非依赖字符串/Buffer隐式分支

### 3.1 候选选择

建议后续只审议一个主候选：**原屏障内显式调用同步，并绑定写入的同一句柄**。
本轮不实现。相较仅把string改成Buffer后继续依赖flush:true，它使同步步骤/失败
出口可直接核对，避免用编码类型偶然选择分支来代表完成保证。不升级Node、不换
客户端、不删已有屏障、不合并多记录同步；Buffer路径仅作备选，不同时开发两套。

原API若不暴露句柄，未来须将该次写入变为拥有句柄的局部操作；禁止先close再按
路径重开后同步，因为文件身份/锁内次序需要额外证明。暂不选择长期持有句柄、
新writer服务、后台flush或目录布局重构，以避免扩大生命周期与恢复变更。

### 3.2 拟议同步顺序与语义

```text
原身份/路径检查和锁边界
  -> 获得属于本次操作的句柄
  -> 写完完全相同的字节（短写只推进尚未写完的范围）
  -> 在同一句柄上显式同步成功
  -> 完成原后续检查、关闭/清理
  -> 方可对调用者发布成功确认
```

这不是对内部state更新顺序的实施许可：原transition、cache失效、checkpoint发布
时点必须逐点映射。若原内部先更新state再写，未来必须证明失败后不会发布该状态，
不能凭图中顺序擅改整套事务模型。已写入但同步失败属于**持久性未知**，不是未写。

- 新同步失败是新增可观察失败出口，需映射到原有证据失败/异常传播通路，并核对
  try外异常、terminal无法落盘、CLI与settlement等区别；不得自行新增运行停止规则。
- 旧close/unlink覆盖优先级保留；同步失败后又发生cleanup失败时，外显优先级须
  明确，不能静默吞错或宣称两条异常均已归档。新辅助诊断若保存须另计编码。
- 部分写后的续写是同一次文件操作的剩余字节推进，不是模型重试；抛错后不得
  自动重写整个记录、重发模型或补样。零进展不算完成，也不新加timeout/kill。
- 覆盖journal、manifest、result、候选stdout、report和receipt等实际要求耐久的
  文件，不只修stdout然后宣称所有历史证据链闭合。

## 4. SC-F：故障模型先分层，不给一个含混的“durable=true”

| 层级 | 允许讨论的保证 | 必须证明/明确排除 |
| --- | --- | --- |
| F0 API/内容完成 | 写入完整、显式同步返回、同一范围回读/hash匹配 | 回读可能命中缓存；不是进程崩溃或掉电证明 |
| F1 进程故障恢复 | OS/文件系统持续正常，仅本进程退出/崩溃后，已确认前缀仍可发现并验证 | 独占身份、文件命名/目录可发现性、receipt恢复规则；不含OS崩溃/掉电 |
| F2 系统/掉电 | 已确认数据和必要目录项在OS崩溃/断电后仍满足合同 | 文件/目录持久化顺序、Windows/FS/驱动/设备缓存保证；当前unknown |
| F3 设备失效/敌对修改 | 介质丢失、静默损坏、外部写者篡改后的可用性/恢复 | 需要额外复制/信任机制；本最小方案不增加此类架构，不能声称覆盖 |

**推荐候选：** 先界定F0+条件F1证明域；F2/F3显式未覆盖，而不是填“通过”。
这只用于候选交付声明。若现有原门槛要求F2，则F0/F1子证书仍不足，维持不准入；
Owner认可故障模型表也不能自动把原F2要求降为F1。本轮不查询/变更卷、缓存策略、
空间配额或权限，不对现有E盘推断其FS/设备资格。

### 4.1 完成/恢复记录的最小收口

不新建第三套数据副本。未来单槽完成凭据应绑定：源head/profile/fault_profile、
result与stdout的文件身份及各自offset/length/hash、前序凭据和实际槽位身份。
可在一个记录中嵌入两个范围描述，避免“固定receipt之外另有未计量配对清单”；
是否替代MC-S的receipt+清单组合需另批，**不得继承其1024 B上界**。
文件路径通过有预算的来源映射或可证明确定性命名解析；hash不替代实际文件。

成功顺序候选：两份数据写完并分别同步/验证 -> 写绑定两份数据的完成记录 ->
完成记录同步/关闭并可发现 -> 返回该槽完成。它不是多文件原子事务，也不引入
自动恢复执行。跨文件崩溃可留下不完整数据/receipt，全部保留，不准覆盖补写旧证据。
不递归生成“证明receipt已完成的receipt”；恢复时依原文件、完整记录和数据验证
建立信任。调用返回前的确认事实与退出后重新验证的事实分别记录，不倒填旧状态。

### 4.2 必须覆盖的失败切点

| 切点 | 允许的结论 |
| --- | --- |
| 数据未写完 / 同步未返回 / 返回错误 | 仅未确认前缀；保留实际部分字节，不宣称未写 |
| 两份数据完整但receipt缺失或部分 | 不提供已确认完成；未来只读可发现材料，不续跑/补发 |
| receipt写完但同步/close/可发现性未证 | 内容可能完整，合同完成仍未证 |
| 完整receipt与两份数据均可验证 | 仅按其fault_profile说明实际前缀；不自动说明576槽或end完整 |
| 任意永久I/O停滞 | 安全性不等于活性；没有有界返回保证，不添加停止条件 |

- [ ] 给F0/F1/F2每项要求明确源码、供应方合同、部署资格或unknown来源。
- [ ] 绑定目录项/文件身份/权限/已有文件与新建文件差异；不把文件同步等同目录同步。
- [ ] 定义成对范围记录、重启只读验证规则、完整编码和全部失败保留成本。
- [ ] 逐切点区分内容合法、交付完成、持久性未知、无法产生诊断四种状态。

## 5. SC-N：只闭合实际可达出口，不再追求所有Node程序的小错误界

限定为本研究具体entry/import图、固定二进制及其构建映射、启动flags/preload、
global fetch/dispatcher/原型、请求/abort生产者与stream传播链。资格profile是
工程附属记录，不改freeze。当前身份不能补签旧批次，未绑定依赖保持unknown。

剩余工作按以下有限列表核对，不扩大为任意JS/OS错误百科：

1. Request构造的实际输入转换及可能原样传播异常。
2. 原研究创建的abort reason及storedError的可达来源；同步新增错误独立列账。
3. 实际入口导入的模块及全局dispatcher/原型写入点，启动链无法读取则记缺口。
4. frozen parser保存message的非语法路径：Buffer/clone/类型/分配异常；明确try外
   退出与进入报告的错误，不能全算成j也不能全排除。
5. Q/N/F/头域是否有对应生产者保证；错误域闭合不替代客户端交付域闭合。

- [ ] 每个出口列producer、实际保存字段、动态输入、次数、编码/驻留传播。
- [ ] 只有源码证实不可达才能排除；“尚未观测到”不是证明。
- [ ] 输出PROVED_CONDITIONAL / UNKNOWN / OUTSIDE_DECLARED_PROFILE及理由。
  最后一类只是证明标签，不是拒收研究输入、忽略失败或不计分的运行策略。

资源耗尽或native致命退出可能没有JS错误/最终receipt；保留已落盘前缀，不能承诺
在任何OOM情况下完整生成错误证据。若全证据要求涵盖此域，须记冲突而非静默排除。
不截断code/message、不规范化冻结错误、不加错误长度上限，不用第二次模型调用。
一次清单完成后仍unknown就返回未闭合，不自动增加异常探测轮数或升级runtime。

## 6. SC-M：完整预算与RSS证明边界

本项不承诺“下一轮静态分析一定给出硬RSS上界”。交付分为：

- M-L：原固定负载及完整旧reader域分别参数化，列同时存活对象、别名、累计分配、
  Error/Script原始源保留、数据/receipt编码、native/FS同步和输出等待成本。
- M-E：只有绑定了布局、native缓冲、GC/allocator及宿主保证的项才给数值。无法
  证明最坏回收时机的项保持unknown；不以heap极限、物理内存或“安全倍率”代替。
- M-V：未来另批原性能系列的每pair RSS<=1.25等门槛；M-L/M-E不改变原采样边界，
  不能把sink或同步开销移出测量。实测通过也不能倒推出全输入硬上界。

```text
新逻辑容量 = MC原核心/report条件项
            + 新成对完成记录/来源映射（取代旧候选组合，不双算或漏算）
            + reader/native失败证据 + scratch/残留
            + 新来源/宿主记录 + 文件系统实际分配开销

新操作成本 = 原全部audit/verify/write屏障及read分母
            + 同步路径差额 + 成对验证读取/完成记录操作
            + 故障残留与恢复只读成本
```

原148.831282 GiB只是条件子项；新配对格式未定时不发布新总容量数字。576槽不
自动限制人工反复审计的失败保留次数；按一次指定工作单元给条件预算，累计保留
另列，不能设置未经批准的保留清理/停止策略。保留旧192 GiB等候选未批准状态。

## 8. Review Focus

- 同步成功后close失败、写后文件身份变化：不得错误发布成功或遗漏旧覆盖优先级。
- 读回命中缓存、目录项未持久化：不得从F0跳到F2。
- receipt部分可读但成对文件不全：不得用单份摘要冒充两份交付完成。
- OOM/native退出无终态：不得伪造完整错误证据、排除失败或补发模型。
- GC/native/进程外队列未知：不得用小JSON界、已释放引用或未计量sink获得RSS PASS。
