# Phase 0.9.7 规则与模型同输入评测协议 v1

基点 `7ebfb5864db2f296add55ca8a30e8e151206c606`。先提交本文件，再写用例和代码。目标：冻结本地规则和未来获准模型的共同输入、评分、预算与安全边界。不要求全量人工双标，不把自动评审当用户真值，不改变 0.9.4–0.9.6 资格结论。

## 受控问题

- 至少 24 个新故事，Dev/Validation 至少各 12；按故事分区，同案前文有/无两个配对单元，不把变体算独立样本。保持候选、排序、状态、当前话语和 Binding 不变。使用合成公开数据；不读旧 Holdout、reserve 或真实 Session。采用作者构造的透明 trace/参考，不是独立盲测。
- 自然改述、复杂否定、同名歧义、证据仅在前文、陈旧/拒绝来源、误导 Binding、非行动话语、历史只读、明确当前目标优先。参考区分「真实意图有目标，但当前输入不足，应澄清」和「无需建议」。正例标必要证据文字，允许更长的真实 span 覆盖它。
- 主指标：给定可见证据时 decision+身份 exact、正确覆盖、已覆盖正确率、wrong identity、负例错误输出；证据准确单列。配对报告 wins/losses/ties 和计数，不将关联记录作 IID。至少 4 个 Validation 有证据的可建议样本、4 个无身份样本、4 个证据开关应改变判定的故事。0.9.6 只读规则是实际本地基线；固定响应 fixture（可使用答案构造）只校验管线，不计为模型效果、不用于选模型。

## 冻结合同与工程门槛

- 仅导出已授权、限量的候选摘要、包内短 handle、当前话语、允许的上一 User turn、绑定的本包 handle；不导出内部 Task/Workspace/Session ID、cut、拒绝原因、候选 ACL、参考答案、分区或已拒前文。前文关闭不读取；前文开采用 0.9.6 完整原文和版本校验。输入连同 prompt/schema 上限 12288 UTF-8 bytes / 3000 估算 tokens，不驱逐候选腾位。无外发数据准备等于授权的含义。
- 输出只有 suggest_active/reference_history/clarify/no_suggestion、当前包 handle 或 null、最多两个可复核的 UTF-16 半开证据。验证请求哈希、JSON、字段、精确原文、handle/status 和预算；已关闭不能给活跃建议。字符串来源和坐标正确不证明蕴含，必须保留「结构通过但语义错误」负控。所有输出仅评测，不连 writer。
- 工程 PASS 要求上述分母满足，全部 author fixture 可走通、授权/预算/证据负控按预期拒绝、配对候选与焦点相同且无未授权来源/ID 暴露。无真人或真模型样本不得宣称模型胜过规则、正式资格或生产自动路由。
