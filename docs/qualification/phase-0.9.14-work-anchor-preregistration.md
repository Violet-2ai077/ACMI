# Phase 0.9.14：显式用户 WorkAnchor 的离线与同模型配对验证（预注册）

基点 `8b1952bc5feda20005eee1b933028b21200ebbcc`。问题不是模型能否复述由 Host 已知的 UUID，而是「经过验证的发起事件」作为最小上下文能否改善同次归属，又不吞没当前的取消、切换或另提目标。入口事实、模型解释与操作授权分别记录。原生 dsh 不启用生产插件或任务状态写入。

## 固定机制

- 独立受信 fixture 发送用户任务卡「继续」事件，不从题面、gold 或模型输出生成锚点。按操作者、Workspace、Session、请求、当前原生 User ID、Task/WorkNode、权限及任务版本、有效期验证。一个请求只认一个来源；相同事件幂等、冲突重放拒绝、旧请求/版本/权限不可借用。只观察发起事实，不把它转成 Binding 或权限。
- A/B 都构造并审计同等 Host 锚点事实；A 不给模型看，B 仅在有效时给 `work_anchor` 的请求级短 ref、来源类别和范围。两臂相同提示、候选、schema、解码，无 Binding。无效/无事件的 5 组 A/B 请求必须逐字相同；不向模型发送内部 UUID、事件 ID、权限或 gold。
- 模型同次输出自然回答、User/Assistant 主归属、意图和相关任务。纯 Host 锚点基线为“有效事件就给发起目标，否则 unresolved”，只用作语义比较的朴素基线，不是生产策略。真实模型批次不挂工具，不能据此宣称工具授权实测通过。
- 离线门槛先行：验证撤权、过期、错 Workspace/Session/操作者/请求、Task/WorkNode 越界、版本错配、重复/冲突重放、同请求换原生 User、缺/伪造 grant 与发起锚点冲突。用 stock dsh 的脚本 adapter 对同一轮两个 lookup 在分派前过滤：只执行有独立明确许可且与锚点同任务的一条，或都不执行。晚到结果仍按原始调用归属；不因当前锚点或任务改变重新判定来源。不测试真实 GUI、原生 Subagent 或逐 token streaming。

## 样本、预算与判定

- 12 个新配对探针、11 个故事簇（前两探针共享真实工作 UUID、不同 dsh Session，用于续接）；共 24 次本地生成。4 个有效续接含 task-only 和主次关系；3 个有效发起但正文冲突（切换、取消、新目标）；5 个无有效锚点含显式自由文本、同名、撤权、引述及错 Session。A/B 顺序交替，同对候选一致，不用历史结果充数。
