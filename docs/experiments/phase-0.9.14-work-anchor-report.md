## 方法与对账

独立合成发起事件源模拟用户点击任务卡「继续」，不从正文、模型输出或真值生成锚点。实际进 stock dsh 0.2.2-rc.1 后，将受权事件与原生 User ID、Session、请求、Workspace、操作者、Task/WorkNode 和版本核对。锚点表达从哪里发起，不授予执行权。撤权模型探针仅撤发起权、保留候选读取；撤读不是本次真实模型测试的一部分。

12 个新配对探针、11 个故事簇；前两探针在不同原生 Session 发起同一长期 Task，事件独立，不当成两个独立故事。A/B 都记录锚点事实，A 不向模型暴露，B 仅在有效时提供短引用。相同 Qwen3-14B Q4_K_M、llama.cpp b12283、同 schema、同候选、同解码、无 Binding 提示。五个无有效锚点配对请求逐字一致，本次输出也逐字一致。真实模型批次不挂工具。

### 模型错在什么地方

- B 在同名、撤销发起权和错 Session 三例都选了正确的 `clarify` 意图，正文也在要求澄清，却把两个主角色标成 `no_task`，而不是 `unresolved`。无锚点的对应 A 输出完全相同。
- 新目标样例两臂都写对 Cedar Audio Cue，也标记 `propose`，但两个主归属仍是 `no_task`，没有可用的新任务提案。锚点没有解决这个已重复观察到的合同不一致。
- 切换例 B 选择了正确的新任务且未沿用旧锚点，但把只描述的请求标成 `execute`，正文未命中冻结名称。它没有执行工具。此例进一步说明模型的意图字段不能当成执行许可。

## 独立授权和因果验证

离线测试覆盖拒绝错 Workspace、Session、操作者、请求，版本变更、撤权、时间窗、Task/WorkNode 不匹配、未知或冲突重放，以及同一个请求试图更换原生 User 事件。相同请求与原生 User 的幂等解析允许使用同一发起事实；跨 Session 续接必须用新的发起事件。原型是进程内 fixture，没有实现生产身份认证、持久去重或真实 UI。

两个 stock dsh 原生脚本测试分别给出两条建议：A 的 lookup 和不属于 A 的 B lookup。单独授予 A 的 lookup 许可时只发派 A，并用原始 Call ID 取回 A 的结果；只有锚点、没有许可时两条都不发派。伪造或失效的许可在纯 Host 测试中被拒绝。另用离线因果测试在旧 A 锚点已过期、新锚点为 B 的情况下查验 A 的晚到结果仍继承原调用。不把脚本工具证据冒充真实模型工具实验，也不从到达时的权限推断历史因果或授予结果读取权限。
