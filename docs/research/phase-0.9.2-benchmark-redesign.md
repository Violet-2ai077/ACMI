# Phase 0.9.2: Benchmark redesign for Phase 0.9.3

**设计已交付，语料未建设，独立终测未冻结。** 目标 800 个评分场景（可接受 600-1,000），以自然度、可复核证据和独立性为准入条件，不用模板复制填数。一个评分场景是一个明确的焦点事件、其当时可见的因果前缀和候选快照；同一长轨迹可有多个焦点，但整条轨迹必须同 split，推断时按轨迹/泄漏组件聚类。后续事件不得作为当时的裁决证据。

## 计划配额

主分层互斥，每案恰归一行；次标签可交叉，不能重复计入总量。表是目标，不是已收集样本数。

- 语言目标每个 split 45% 中文、35% 英文、20% 自然中英混合（总计 360/280/160）。由不同作者独立构造，不用翻译复制；双语作者检查 code-switch 的自然性。
- 10-30 turns 的长对话至少 160 案（80/40/40），记录实际 turn 数及缺失前缀；每个 split 包含状态跨轮更新、干扰插话、角色/Session 边界及隐式指代。显式关键字不可成为类别捷径。
- 终测次标签最低目标：跨 Session 20、A/B/A 12、三任务及以上交替 10、相似目标 20、用户纠正 12、纯讨论 12、候选存在但错 10、候选为空/缺真正目标 10、上下文缺失或截断 12、注入/良性对照各 10。这些标签可重叠，并分别公布分母。跨 split 的比例与组件数在冻结前审计；若约束冲突，增加独立组件或调整配额并记录，绝不拆组件。
- 采样纳入同一事实的难负例：同主题不同验收目标、同目标不同阶段、讨论不等于授权、Subagent 完成不等于接受/Join/关闭、内容缺失不等于用户无任务。文案独立撰写；构造配对、删减/翻译变体均同组隔离，不让变体数量主导置信区间。

## 编写、筛选与防泄漏

1. 签收来源登记（作者/批次、授权和来源类别），默认独立合成且不使用真实用户 Session。记录 `constructionFamilyId`、`linguisticPatternId`、`taskFixtureId`、`trajectoryId`、`derivationId`；作者与 reviewer 角色隔离，匿名化后公开只读 case ID，不暴露分层标签、标准答案或作者设计备注。
2. 三种分组 ID 中任意一个相同，或属于同一对话、翻译、改写、裁剪、对抗配对、共同生成模板或同一素材源，即建连接边；对传递闭包组件分割，不能仅按三元组分割。先锁定各组件归属再出包。执行规范化精确 SHA-256、字符/词 n-gram 近邻（分别覆盖中英）、去实体/数字后的模板指纹、Task 图结构和目标近邻审计；人审跨 split 近邻和相似结构，疑似未解除则合并同组或隔离。冻结前记算法、阈值、抽样、处置、组件数与统计；外部保管人执行终测近邻审计，仅回传不含题面/标签的违规组件位置或合格摘要。
3. 自然度和可标性筛检：焦点明确、历史与图状态时间一致、证据真实可引用、未提供的前缀明确缺失、可分辨数据缺失和可接受的多解。不用内部预期答案解决分歧。所有资格评分样本须具备经核验双标及必要仲裁；若无法承担，先缩到 600 仍保持关键层最低配额，不能称未完成双标的层为人类真值。
4. Dev 可迭代；Validation 用于少量预登记版本比较、阈值与提示选择，并记下每次接触。资格评估冻结后不得调参。0.9.1 原 216 例已消费，只允许 `retrospective_analysis_only`，不评分、不调优、不改名、不分配给新语料或新终测，冻结/消费原件不改。0.9.1 旧 Dev/Validation、0.9.2 原型题及本次公开标注演练均不计入上表或资格证据；禁止从历史错误案例改写出新终测。

## 新终测的独立保管与单次消费

| 阶段 | 外部保管人职责 | 研究团队可见 |
| --- | --- | --- |
| 预注册 | 独立于题目开发、Prompt 和模型选择的保管人确认分组、访问控制和离线近邻隔离；批准独立作者名单；题目和标签分别加密存放，最小权限、访问留痕 | 协议、目标配额、元数据汇总；不见题面/ID 映射/答案 |
| 双标与冻结 | 给已核验 reviewer 独立分发各自只读题面，不给模型方；隔离提交和仲裁；冻结输入、合格 adjudicated labels、split/group manifest、evaluator、协议和候选快照；记录各自 SHA-256、UTC、批准人、变更号 | 签署的冻结 receipt 与 hashes；不见内容、盐值、单题反馈 |
| 单次资格评估 | 启动前再验 hash、批准清单、代码/Prompt/配置承诺；用不可并发的单次消费记录，以首次访问题面用于评分/尝试启动执行为消费点；所有预注册 arms 同一批由保管人执行；日志失败也不复位 | 事先约定的聚合/分层结果、错误及费用计数、审计 receipt |
| 事后 | 泄漏、误配置或非计划停机标记 `consumed_invalid`，不得覆盖/重试；如需重测另构独立终测。若解封逐题，永久转 retrospective，任何再用不构成独立验证 | 原样保留结果和失败记录；仅对新协议重新申请资格 |

没有外部保管人、已验证双标和单次消费记录，就没有可报告的 Phase 0.9.3 盲终测。当前开放演练见 [人工标注计划](phase-0.9.2-human-annotation-plan.md)；实验授权及公平比较见 [真实模型评测协议](phase-0.9.2-real-model-evaluation-protocol.md)。
