# 任务理解问题模型 v0.1

## 理解什么，不理解什么

ACMI 不是从一句话猜一个 Task ID。它要回答四个可分别出错的问题：这句话在做什么、它与哪项工作有关、那项工作是谁、有什么有证据的变化值得提出。最后还要回答另一个独立的问题：谁有权修改持久状态。把五个问题折成一次五分类，容易把“谈 B”变成“切到 B”、把“工具成功”变成“任务完成”，或因为找不到 B 而漏掉“用户确实要求切换”。

| 层 | 输入和输出 | 明确不做 |
| --- | --- | --- |
| L0 事实 | Host/Adapter 认证的 Session、actor、turn、cursor、Tool/Subagent 因果、既有 Binding 和 revision；原文片段只是来源证据，不因出现在 Journal 就变成授权 | 不从文字生成 Runtime Fact |
| L1 言语行为 | 可多标签、可分 span：询问、报告、建议、拒绝、选择、接受、纠正、授权动作；标记引用、否定、条件、说话人 | 不把历史引用视为当轮命令；不由 Assistant 代表用户 |
| L2 工作意图 | 每个 span 分别输出关系（无工作、仅讨论、现有、新工作、不明）、执行姿态（讨论、继续/切换请求、延后/等待、不明）、语义变化（保持、细化、范围/目标变更、状态请求、不明） | 不赋 UUID，不判断能否执行，不自动绑定 |
| L3 身份 | 每个指称独立解析：已解析、歧义、缺失、已关闭、超出授权、陈旧、待分配；可澄清。内部 scope-denied 不公开跨权限实体信息 | 不更新 Session 焦点事实，不把同名/文本相似当同一 Task |
| L4 结构 | 分别生成 Task lifecycle 草案和 WorkNode/Decision/Constraint/Dependency/Result/Join 草案，附证据与不确定原因。一个已解析意图可以有零个、多条或相互冲突的草案 | 不写 Graph Store；不把运行结果当语义结果 |
| L5 授权 | 既有可信 Host 展示、显式确认、按当前 scope/revision 再校验、原子审计或拒绝；无授权一律没有副作用 | 模型、规则、候选排序、实验驱动都不进入 writer |

L1–L4 是逻辑依赖，不要求每层都调用模型。一次有界响应可以包含多个层的字段，但验证、诊断和弃权应分别保留。L3 可以供 L2 做有界重审（例如识别引用），不可用「没找到候选」覆盖明确的切换姿态。L4 的图草案以 L3 和证据为依赖，仍可单独弃权；有正当的 clarify 或 draft 时不强迫同时输出其他层。

Phase 0.9.1 的 `create_new/continue_current/switch_existing/no_task/uncertain` 只保留兼容投影，无法表达多行为、讨论、歧义、细化或仅需创建草案的区别。不得用投影控制 Host。`no work` 是有证据的不涉及工作；`discussion` 是涉及工作但没有执行/控制授权；`unknown` 是证据不足，三者不可混用。

## 状态的正交性

| 状态面 | 身份与事实 | 可以提出的语义，尚非事实 |
| --- | --- | --- |
| Task | 持久 UUID、Workspace 范围、当前已提交 lifecycle、Binding revision | 新建、复用、细化/更改目标、暂停、重开或被替代；未有安全 reducer 的动作仅记录为草案 |
| WorkNode | 一项 Task 下的局部对象与版本，可依赖其他节点 | 拆分、等待、阻塞、证据满足、建议关闭；节点变动不换 Task |
| 执行 | Tool Call/Result 和 Subagent 事件按 Host 因果键关联 | “完成的执行产物供人查看”不是 WorkNode 或 Task 完成 |
| Result | 产物证据、提交的 result node 与消费/接受证据分别记录 | 提出可供消费、已被明确引用、待接受；生产、消费、接受是三个动作 |
| Join | 观察到分支或结果，不等于 join predicate 已满足 | 可以解释缺哪些证据；不产生自动满足动作 |
| 会话 | 当前 Binding 与解释时的候选焦点两条线 | A→B→A 的焦点假说不能覆盖 Host 绑定；重启只恢复有效范围的状态 |

## 决定、结果、依赖的例子（新写说明例，不是历史 Holdout）

- “问一下导入任务怎样了，先别切过去。”：命名实体 + 询问/否定切换；若导入 ID 已知，可返回只读引用，不能调用 switch。
- “先停发票修复；开一个项目研究税额显示。”：两个 span、两个关系；暂停是生命周期请求，新工作没有 UUID。确认第一个不授权第二个。
- “助手说用队列，我反对；保留同步模式。”：引用建议不是接受；用户明确反对和正面选择分别保留证据，受信 Host 处理后才生效。
- “子代理报告迁移脚本写完；我只看过文件名，明天跑 smoke。”：工具/子代理完成可以是事实，测试和消费尚未发生，更没有 Task 完成。
- “A 等 B 的 checksum 核对；只有文件存在还不够。”：可提依赖和验收条件，方向与 source span 一起提交；B 返回成功日志不满足 Join。
- “恢复上周那个压缩优化。”：请求姿态清楚，身份可能含两个同名 Task 或 closed tombstone；向用户澄清，绝不创建同名 Task 顶替。

## 可区分的错误和不可识别因果

度量以 scenario 为基本单位，保留多 span：言语行为错误、意图错误、候选缺失、identity 误解析、scope/证据违规、结构漏检、过时或错误 apply、错误弃权分别计数。区分有标签但弃权与本来无证据；测试 L3 时报告 oracle-candidate 与真实 retrieval 两条指标，不能把候选集不存在的实例都归给 decoder。旧归档只看见最终预测和有限输入统计，不足以分辨“模型没看见”“未检索”“理解失败”等机制；相关性或主题不当作因果证明。

参考：[SGD 的 schema-guided dialogue state tracking](https://ojs.aaai.org/index.php/AAAI/article/view/6394) 提供分层状态建模的外部先例。ACMI 的持久身份、权限与提交门槛是新增工程约束，不由 SGD 验证。
